# 设计审美工坊

用户说中文时用中文。先判断交付物、读者、最重要的动作或结论、现有品牌约束和输入材料。看得到截图、代码、现有设计系统或数据时先读它们。用户指定品牌、参考、平台或明确风格时据此直接做。简单任务补上可逆的合理假设。只有缺失的信息会实质改变用途或交付物时才问。

## 从用户的话判断任务

| 用户怎么说 | 要做什么 | 读取 |
| --- | --- | --- |
| 选风格、三版方案、找包豪斯/侘寂、给一份 DESIGN.md | 查风格并给有用途差异的方向，或者把指定方向写成可执行规范 | [风格和资料](references/styles.md) |
| 做网页、做 App 原型、改版、做可编辑 PPT | 优先根据素材与使用情境定结构，再落到对应格式和验证 | [制作网页、原型和 PPT](references/build.md) |
| 审美体检、去 AI 味、critique、audit、polish、bolder、quieter | 按任务范围看证据，评审或实施，再验证影响 | [评审与改版](references/review.md) |
| 流程图、架构图、时序图、信息图、数据图表 | 先确定图的关系或数据，再决定图种、版式、交付格式 | [图表与示意图](references/diagrams.md) |
| 查原项目、来源、授权 | 查固定版本及对应授权文本 | [上游来源](references/sources.md) |

一个请求可以连续走多个环节，例如先评审再改版。只提到做设计时，直接交付可以实现的产物。用户说「先看看方案」或要求几版对比时，给 2–3 个结构确实不同的方向，并根据需求说明选择理由。选定后沿同一规则完成页面、幻灯片或图表。

## 统一的交付标准

1. 让层级服务任务。首页先让人明白主体和下一步，后台先让人完成操作，汇报先传达结论，图表先呈现关系或数字。一个页面或画面有一个明确主视觉。
2. 把风格写成可执行决策。明确版式、色彩角色、字体与中日韩字形回退、间距、边框、圆角及动效。沿用现有变量和组件，复用统一的视觉语言。素材和文案围绕用户真实内容。
3. 视觉选择要有依据。给摄影、纹理、渐变、卡片、动效或装饰分配明确用途。优先查真实素材和品牌现有规范。文案和数据缺失时使用可识别的占位，避免把演示数字、宣传语或客户评价写成事实。
4. 实际制作时按交付物选择当前环境的网页、图表或演示文稿能力。使用工具检验渲染、尺寸、交互和关键状态，有问题就修。汇报时如实写出用了哪些材料和实际检查过的范围。

相对路径以本 `SKILL.md` 所在目录为准。能运行 Python 3 时，按[风格和资料](references/styles.md)调用随包脚本，查目录、输出 CSS 变量、生成离线 HTML 样张或计算对比度。只有文件读取能力时，从 [流派索引](references/catalog/README.md) 或 [图种索引](references/catalog/diagrams.json) 查所需条目。根据当前 AI 的文件、图片和代码能力交付实物或设计规范，如实说明可以验证的范围。
