# 图表与示意图

先确定读者需要理解的是顺序、分支、层级、依赖、变化、归因、分布、流量还是对比。核对原始节点、关系、数量和单位。照片和生图适合视觉素材，节点关系、文字和数字使用结构化图表或图形工具。

| 关系或问题 | 优先考虑 |
| --- | --- |
| 带条件与回路的步骤 | 流程图，清楚标注分支条件、终点和返回箭头 |
| 谁负责哪一步、在哪里交接 | 泳道图或服务蓝图，泳道对应真实责任方 |
| 谁先发消息、谁响应 | 时序图，区分调用、返回和失败路径 |
| 系统由什么组成、怎样连 | 架构图或数据流图，注明边界和连接的含义 |
| 按时间发生或持续 | 时间线或甘特图，日期和持续时间使用真实尺度 |
| 比多少、升降、分布、相关 | 分别优先条形图、折线图、分布图、散点图 |
| 总量如何分配或流动 | 矩形树图或桑基图，写清单位和总量 |
| 原因怎么归类 | 鱼骨图，把已知证据和待验证假设写清 |

完整的 50 项图种与画法见[图种索引](catalog/diagrams.json)。在 `SKILL.md` 所在的 `design-studio/` 目录运行 `python3 scripts/design_catalog.py search 泳道 --source diagram`，可查中文名称、同义词、版式要点和上游说明。

## 排版和准确性

用统一字号、箭头语义、线型和节点间距。默认沿一个阅读方向排列，保留连接的呼吸空间，优先减少交叉、反向线和重复标签。主路径突出，次要路径可用线型或文字区分。颜色表示类别或状态时提供图例或直接标签。层级过多时先给总览，再按需要分图。

用真实刻度和来源，保留单位、日期、样本和缺失值。条形图优先用零基线。百分比应明确分母。检查箭头方向、关系、顺序和数字与用户材料一致。长中文标签用短语或合理换行，复查最终尺寸的可读性。

## 选择交付格式

对话里的简单映射优先 Markdown 表格。拓扑、分支或时序可在支持的界面用 Mermaid。需要设计稿、印刷或导出时按请求制作 SVG、PDF、可编辑幻灯片或自包含 HTML，验证画面边界、中文字体、标签位置和导出尺寸。用户明确要求某种格式时以该格式为准。
