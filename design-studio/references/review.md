# 审美体检与修改

用户给截图时，评审具体页面区域或可见状态。给 URL 时用可用的浏览器检查获得可见证据。给代码时查看正常入口和现有设计系统，能运行就复现。只有截图的场景可以指出布局或文案问题，精确的性能、DOM 无障碍和真实交互留待代码或浏览器验证。

| 指令 | 怎么执行 |
| --- | --- |
| 体检、去 AI 味、`critique` | 检查用途是否一眼能懂，主信息是否突出，版面是否依赖重复模板，文案和素材能否对应项目。输出位置、证据、影响及可实施的修法。 |
| 技术审查、`audit` | 看键盘、焦点、语义、对比、断点、加载、性能与状态。指出复现条件，区分观察到的问题和待验证的线索。 |
| 精修、`polish` | 沿当前视觉方向修复对齐、节奏、字级、颜色细节及状态，让用户操作路径闭合。 |
| 大胆点、`bolder` | 选择一个值得加强的主视觉，用字号、构图、图片尺度、留白或强调色建立对比。 |
| 安静点、`quieter` | 收拢装饰、视觉噪声和大面积强调，保留可识别的主行动、状态提示和阅读对比。 |
| `clarify`、`distill`、`layout`、`typeset` | 分别改善表述、精简内容、重排布局、处理字级和阅读节奏。 |
| `adapt`、`harden`、`optimize` | 分别修响应式、异常与边界状态、加载和交互性能。 |
| `colorize`、`animate` | 按语义设置颜色和动效。状态有文字、形状或图标辅助，尊重减少动态效果的系统设置。 |

## 检查顺序

- **内容与任务**：前两眼看见什么、下一步能否找到、标题是否提供真实信息。删掉只占空间的标签、同义重复和空泛宣传语。
- **布局与排版**：看对齐基线、标题长短、间距关系、固定区与滚动区、窄屏断行。密集页面优先可扫读，营销页面优先形成视线重心。
- **视觉和素材**：区分有效强调与装饰。检查重复卡片、失控渐变、无依据的图标、假数据、图片裁切和光影冲突。用户明确需要的玻璃质感或渐变仍按选定风格做，并检查可读性。
- **真实状态**：表单错误能否就地理解、加载后布局是否跳动、焦点和选中是否可辨、字号变化后是否遮挡、动效关闭是否仍能使用。

报告优先列最影响用户完成任务的 3–6 项，每项包含页面位置、可见证据、造成的影响和改动建议。修改时优先修断点和主要操作，再处理细节。修完实际走一遍关键路径，能渲染时检查代表性的宽屏和窄屏。可观察的功能问题可以独立记录，避免混进审美判断。
